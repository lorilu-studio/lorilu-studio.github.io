想做一个带孔的矩形板，用文字描述并不难。板子长多少、宽多少、孔在哪里，给 AI 说清楚就行。真正麻烦的地方在后面，孔有没有打穿？尺寸对不对？下次想把板子加宽，能不能方便地修改？

[text-to-cad](https://github.com/earthtojake/text-to-cad) 想让 Coding Agent 帮忙处理这类工作。你用自然语言描述零件，Agent 编写参数化 CAD 脚本，运行后在 Viewer 里查看模型，再根据检查结果修改脚本、重新生成。

这篇文章根据项目文档和公开资料整理，安装方式核对于 2026 年 11 月 1 日。下面的矩形板是供读者尝试的示例，文中没有把它当成已经完成的本机实测。项目更新较快，实际操作时请以[官方安装文档](https://github.com/earthtojake/text-to-cad/blob/main/docs/install.md)为准。

## 先认识一下 text-to-cad

text-to-cad 是一套给 Coding Agent 使用的插件、技能和本地 CAD 工具。按照项目的说明，Agent 用 Python 和 build123d 编写模型脚本，cadgen 负责运行和构建，CAD Viewer 用来查看结果。需要交付文件时，可以要求导出 STEP、STL、3MF 或 GLB 等格式。

从需求到导出，检查发现问题后可以回到源码修改，再重新构建。

![从描述需求到生成、检查、修改和导出 CAD 模型的流程](/images/20260809-text-to-cad/01-cad-workflow.png)

STEP 常用于 CAD 软件之间交换几何模型；STL 通常用于网格和 3D 打印流程。STEP 不保证在所有软件里保留原始参数和建模历史，所以请同时保留生成模型的 Python 源码。后面要改尺寸，有源码会方便得多。

项目还提供 DXF、机器人描述文件和制造检查等相关技能。第一次使用时，先把一个简单零件做出来，熟悉生成和检查过程就够了。

## 安装前准备什么

下面以 Codex 为例。你需要已经能够使用 Codex，有可联网下载依赖的环境，并准备一个单独的工作目录保存模型源码和导出文件。项目也支持 Claude Code 等其他 Agent，各自的安装方式见[官方文档](https://github.com/earthtojake/text-to-cad/blob/main/docs/install.md)。

项目提供一键安装脚本，也提供按应用安装的方式。一键脚本会检测本机 Agent 应用并安装或更新对应组件，可能安装 `uv`，还会处理旧版本组件。想先看它准备做什么，可以参考官方文档下载脚本并运行 `--dry-run`。下面只介绍给 Codex 单独安装的方法。

根据目前的官方说明，先安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)，然后在终端执行。

```bash
codex plugin marketplace add earthtojake/text-to-cad --ref latest
codex plugin add text-to-cad@earthtojake
```

完成后重启 Codex。按照官方文档，插件会提供技能和 CAD Viewer 所需的本地服务；首次启动可能需要联网下载运行环境。如果之前已经通过插件目录或其他方式安装过同一个插件，先检查已有版本，避免重复加载。

项目说明默认会发送使用统计和崩溃报告，并称这些报告不包含模型、文件路径或提示词。可以在 Viewer 菜单关闭遥测，或者让 Agent 帮忙关闭；具体行为见[隐私说明](https://www.texttocad.dev/privacy-policy)。你使用的 Agent 服务也可能有自己的数据处理规则。

## 第一个零件，做一块带孔的板

新建一个工作目录，在这个目录打开 Codex。下面的例子选择矩形板，是因为外形和孔位都容易核对。把这段需求发给 Agent。

```text
请使用 text-to-cad 的 CAD 技能创建一个参数化矩形板。

单位使用毫米。板沿 X、Y、Z 方向的尺寸分别为 80、50、6。
板的底面位于 Z=0，板的中心在 X=0、Y=0。
在板的中心创建一个直径 10 的圆形通孔，孔轴沿 Z 方向，贯穿整个厚度。

请保留 Python 建模源码，构建模型并在 CAD Viewer 中展示。
测量并报告整体尺寸、孔的直径和孔的位置。
请先展示检查结果；如有不符，修改源码并重新检查。确认后导出 STEP 文件，告诉我源码和 STEP 文件的位置。
```

这里把坐标原点、单位和通孔方向都写了出来。假如只说“做一块中间有个洞的板”，Agent 仍然可能给出结果，但它需要自行猜测尺寸、板厚和孔的方向。猜得越多，后面越难判断哪些地方符合你的想法。

Agent 可能会先下载运行环境，再编写脚本。构建成功后，要求它给出源码路径和模型页面或 Viewer 链接。检查通过并导出后，再确认 STEP 文件的位置。不同版本和 Agent 界面的显示方式可能不同，终端环境通常需要打开浏览器链接。

如果没有看到 Viewer，先让 Agent 检查插件是否加载、`uv` 和 cadgen 是否可用，并阅读报错。官方建议遇到环境问题时使用 `cadgen doctor` 收集诊断信息；插件安装和疑难问题也可以查[安装文档](https://github.com/earthtojake/text-to-cad/blob/main/docs/install.md)。不要在没有弄清报错时反复重装或删除已有配置。

## 怎么检查这个模型

先在 Viewer 里转动模型，从正面、侧面和底面看看。正面能看到孔，不代表孔一定贯穿了整块板；侧面和底面能帮助发现明显的方向或穿孔问题。

再请 Agent 测量几何并报告结果，至少核对这些数值。

- 外形包围尺寸应为 80 × 50 × 6 mm。
- 圆孔直径应为 10 mm，孔轴沿 Z 方向。
- 孔中心位于 X=0、Y=0，孔贯穿整个板厚。
- 板底面位于 Z=0，顶面位于 Z=6。

这些是示例的验收条件。截图能帮助发现形状和方位问题，尺寸仍要靠测量；Agent 的报告也值得结合 Viewer 或其他 CAD 软件再次核对。检查后打开导出的 STEP 文件，确认文件可用，别只看聊天里的预览图。

Hacker News 上有使用者提到，让 Agent 从多个角度渲染并查看模型，有助于发现问题。这是一条值得尝试的经验，具体效果仍取决于模型、任务和所用 Agent。[讨论原帖](https://news.ycombinator.com/item?id=47970497)里也有人提到，复杂零件本身就很难用语言准确描述。

## 改一次尺寸，看看迭代过程

模型检查完，可以接着发一条修改要求。

```text
请把矩形板沿 X 方向的长度从 80 mm 改为 100 mm，Y、Z 方向的尺寸保持不变。
孔仍位于板的中心，直径保持 10 mm，并贯穿板厚。
请修改原有源码，重新构建并检查尺寸，然后重新导出 STEP 文件。
```

这一步要检查的不只是长度。孔是否仍在中心、其他尺寸是否保持不变，同样需要核对。也请 Agent 告诉你更新后的源码和 STEP 文件在哪里。

导出文件是某一次构建结果的快照。修改源码并重新构建后，记得重新导出，否则手里的 STEP 可能还是修改前的版本。每次只改一两项要求，也更容易看出问题出在哪一步。

## 提示词怎样写得更清楚

上面的例子可以扩展成自己的零件需求。写提示词时，先把影响几何形状的信息交代清楚。

1. **尺寸和单位**。给出长宽高、厚度、直径等具体数值，说明使用毫米还是其他单位。
2. **坐标和参考面**。说明原点在哪里，哪个方向朝上，尺寸从哪个面开始量。
3. **孔与其他特征的位置**。写清中心坐标、孔轴方向，说明是通孔还是盲孔。
4. **零件之间的关系**。有装配时，说明哪些部件需要独立，哪些面需要对齐，以及预期的间隙。
5. **交付和检查要求**。要求保留源码、展示模型、测量关键尺寸，并明确需要导出的格式。

描述不完整时，让 Agent 先列出缺失信息和自己的假设，比直接接受它猜出来的尺寸更稳妥。如果有工程图或实物照片，也要提供比例或实际尺寸；只有图片通常不足以确定真实大小。

## 什么时候可以继续往复杂处走

矩形板跑通后，可以尝试法兰、阶梯轴或 L 型支架，再逐步增加多个零件和装配关系。每增加一个新特征，就多检查一次它的尺寸和位置。

[Text2CAD-Bench 论文](https://arxiv.org/abs/2605.18430)评测了不同复杂度的文字生成参数化 CAD 任务。论文作者报告，参测模型在基础几何上表现相对较好，遇到复杂拓扑和高级特征时表现会下降。这项研究评估的是相关模型和基准任务，不能直接当作 text-to-cad 项目的成绩。

项目作者在 [Hacker News 讨论](https://news.ycombinator.com/item?id=47970497)中提到，最初开发这个工具与自己设计七自由度机械臂有关。机械臂听起来很吸引人，但完整装配涉及零件关系、运动范围和干涉检查。刚开始使用时，先让单个零件的尺寸可靠，再考虑把零件组合起来。

对于要制造、承重或用于安全相关用途的模型，还需要有经验的人核对材料、公差、受力和制造工艺。成功导出 STEP，只说明拿到了一个文件，后续工程判断仍需要认真完成。
